🔀 Transformations: Narrow vs Wide Dependencies DAG Scheduler
Narrow (Pipelined)
  • map, filter, withColumn, union
  • Each parent partition used by at most 1 child partition.
  • Zero network shuffle! Pipelined in memory within the same stage.
Wide (Shuffle Boundary)
  • groupBy, join, distinct, repartition
  • Multiple child partitions depend on parent partitions.
  • Forces network exchange; terminates stage and starts new stage!
🌪️ The Shuffle Engine: Write, Read & Spill Shuffle
  • Shuffle Write: Mappers write records to memory buffer; sorted and written to a single .data file with .index offset file on local NVMe disk.
  • Shuffle Read: Reducers fetch their required blocks over Netty RPC from all mappers across the network into local memory buffers.
  • Spill (Memory) vs Spill (Disk): Occurs when shuffle memory exceeds executor threshold. Data is serialized and flushed to disk (huge latency penalty!).
⚠️ Triage Spills: If Spark UI shows Spill (Memory) / Spill (Disk), immediately increase executor RAM, enable AQE, or increase shuffle partitions!

📐 Cluster Sizing & Resource Allocation Math Infrastructure 
# Production Cluster Allocation Formula
# Example: 10 Nodes, 16 Cores & 64GB RAM each
1. Cores per Node = 16 - 1 (OS/YARN) = 15 Cores
2. Cores per Executor = 5 (Sweet spot for HDFS/ADLS IO throughput)
3. Executors per Node = 15 / 5 = 3 Executors
4. Total Executors = (10 Nodes * 3) - 1 (Driver) = 29 Executors
5. RAM per Node = 64GB - 1GB (OS) = 63GB
6. RAM per Executor = 63GB / 3 = 21GB
7. Memory Overhead = max(384MB, 0.10 * 21GB) = ~2.1GB
8. Executor Heap = 21GB - 2.1GB = ~18.9GB (Set: --executor-memory 19g)
⚡ Parallelism Rule: spark.default.parallelism = total_executor_cores * 2 to 3 (For 145 cores = ~300-450 partitions).

🚀 Databricks Photon Native Vectorized Engine Photon
  • C++ Native Execution: Replaces Tungsten Java bytecode execution path entirely with hand-optimized native C++.
  • SIMD Vectorization: Processes batches of column values in CPU SIMD registers simultaneously (Single Instruction, Multiple Data).
  • Zero JVM Overhead: Eliminates Java object allocation, GC pauses, and JIT deoptimizations for high-concurrency SQL and aggregations.
⚡ Accelerated Operations: Delta Parquet scanning, complex hash joins, high-cardinality aggregations, and string/regex operations execute up to 5x faster on Photon.

⚠️ Data Skew Root Causes & Solutions Skew Remediation
  • Root Causes: High frequency keys (e.g. NULL customer IDs, default dummy values, power-law Pareto distributions).
  • Strategy 1 (AQE): Ensure spark.sql.adaptive.skewJoin.enabled = true (Databricks default).
  • Strategy 2 (Null Separation): Filter null keys into a separate stream; join only non-nulls; UNION ALL nulls back.
  • Strategy 3 (Broadcast): If one table fits in RAM (<8GB on large clusters), broadcast it to eliminate shuffle completely!
