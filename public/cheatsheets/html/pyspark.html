🧱 DataFrame Projections, Transforms & Filters DataFrame API 
df_curated = (df_raw
    # Filter with pushdown predicate
    .filter((F.col("status") == "ACTIVE") & (F.col("amount") > 0))
    # Multi-column projection and derivation
    .withColumn("tax_amt", F.round(F.col("amount") * 0.18, 2))
    .withColumn("customer_tier",
        F.when(F.col("amount") >= 10000, "PLATINUM")
         .when(F.col("amount") >= 2500, "GOLD")

    # High-performance projection replacing select() + withColumn()
    .selectExpr("customer_id", "amount", "tax_amt", "customer_tier",
                "current_timestamp() as ingested_at")
)
🔍 Code Breakdown & Engine Mechanics:
  • Filter Pushdown: .filter(...) generates a Catalyst Filter operator pushed down into Parquet footer metadata to skip non-matching row groups.
  • F.when().otherwise(): Compiles directly into native JVM conditional bytecode; avoids python UDF context switching.
  • selectExpr(): Evaluates mixed column projections and SQL expressions in a single projection pass without intermediate plans.
  • withColumns() in Spark 3.3+: Pass a dictionary to add multiple derived columns simultaneously without rebuilding schema trees.
💡 Optimization: Chain transformations lazily; Catalyst combines consecutive filter and project operators into a single pipelined stage.

  • Synthetic Salting: Distributes skewed hot keys across 10 virtual partition buckets, eliminating straggler tasks holding up the stage.

🪟 Analytical Window Specifications (pyspark.sql.Window) Analytics 
# Define Window Specifications
w_dept = W.partitionBy("dept_id").orderBy(F.col("salary").desc())
w_roll_7d = (W.partitionBy("account_id")
             .orderBy(F.col("txn_date").cast("timestamp").cast("long"))
             .rangeBetween(-7 * 86400, 0)) # 7 days in seconds

df_analyzed = (df
    .withColumn("dense_rank", F.dense_rank().over(w_dept))
    .withColumn("prev_salary", F.lag("salary", 1, 0).over(w_dept))
    .withColumn("salary_diff", F.col("salary") - F.col("prev_salary"))
    .withColumn("rolling_7d_total", F.sum("amount").over(w_roll_7d))
)
🔍 Code Breakdown & Engine Mechanics:
  • W.partitionBy().orderBy(): Directs Spark to sort rows within partitioned subsets without sorting the entire distributed dataset.
  • rangeBetween(offset, 0): Computes rolling aggregate windows across epoch timestamps, properly accounting for days with missing records.
  • F.dense_rank(): Computes ranking without rank number gaps for tied values; ideal for identifying top-earners per department.
  • F.lag(col, offset, default): Inspects prior record values in a single streaming pass across the partition window.
💡 Range vs Rows: rangeBetween handles continuous value ranges; rowsBetween operates strictly on physical row indices.

import pandas as pd
from pyspark.sql.functions import pandas_udf

@pandas_udf(T.DoubleType())
def calculate_vat(amount: pd.Series, rate: pd.Series) -> pd.Series:
    # SIMD Vectorized NumPy/Pandas calculation in Python worker
    return (amount * (rate / 100.0)).round(2)

df_with_tax = df.withColumn("vat", calculate_vat(F.col("amount"), F.col("tax_rate")))
🔍 Code Breakdown & Engine Mechanics:
  • Apache Arrow Zero-Copy: Transmits column chunks between JVM and Python workers in Apache Arrow columnar format without row serialization.
  • Vectorized Execution: Python calculations execute on whole Pandas Series using vectorized C/SIMD loops instead of slow row-by-row iteration.
  • Throughput Speed: Executes up to 100x faster than standard Python @udf, eliminating Py4J bottleneck latency.
  • Memory Batching: Tune batch sizes via spark.sql.execution.arrow.maxRecordsPerBatch (e.g. 10,000) to balance RAM usage.

📦 Partitioning Strategy (repartition vs coalesce) Partitioning 
# repartition(N): Full shuffle, balances partitions uniformly
df_shuffled = df.repartition(200, "region")

# repartitionByRange: Sorts data across partitions for range queries
df_ranged = df.repartitionByRange(50, F.col("txn_date").desc())

# coalesce(N): Merges partitions locally WITHOUT full network shuffle!
df_collapsed = df_shuffled.coalesce(10)

# Inspect partition distribution
print("Partition Count:", df_collapsed.rdd.getNumPartitions())
🔍 Code Breakdown & Engine Mechanics:
  • repartition(): Executes a full cluster network shuffle; essential when increasing partitions or redistributing skewed datasets.
  • repartitionByRange(): Uses sampling to determine partition split points, producing globally sorted outputs across partition boundaries.
  • coalesce(): Merges adjacent physical partitions within executors without network transfer; only use when decreasing partition count.
  • File Target Sizing: Adjust partition counts prior to writing Delta tables to maintain 100MB-1GB target Parquet files.
⚠️ Anti-Pattern: Calling coalesce(1) on large datasets collapses upstream execution to a single executor, triggering Driver OOM!
💾 Storage Levels & Memory Persistence Memory Management 
from pyspark import StorageLevel

# Deserialized in RAM (Fastest CPU, Highest RAM)
df.cache() # Shorthand for persist(StorageLevel.MEMORY_AND_DISK_DESER)

# Serialized in RAM with Disk Spill (Production Recommended for Large DFs)
df.persist(StorageLevel.MEMORY_AND_DISK_SER)

# Trigger materialization with an action
record_count = df.count()

# Crucial: Unpersist when downstream processing completes!
df.unpersist(blocking=True)
🔍 Code Breakdown & Engine Mechanics:
  • cache() vs persist(): cache() defaults to deserialized objects in memory; persist() allows customizing serialization and disk spill.
  • MEMORY_AND_DISK_SER: Stores serialized byte arrays; reduces RAM consumption by ~3x and prevents out-of-memory errors via local disk spill.
  • Lazy Evaluation: Persisting is registered lazily; data is only populated into cache blocks when the first action (e.g. .count()) is invoked.
  • unpersist(blocking=True): Explicitly frees cluster memory immediately, preventing memory leaks across long-running pipelines.
⚡ Off-Heap Option: StorageLevel.OFF_HEAP stores data in Tungsten managed memory outside the JVM garbage collector, eliminating GC pauses!
🌊 Streaming Microbatch Merges (foreachBatch) Streaming Sink 
def upsert_microbatch(microbatch_df, batch_id):
    # Idempotent write per microbatch
    (DeltaTable.forName(spark, "silver.realtime_orders").alias("t")
     .merge(microbatch_df.alias("s"), "t.order_id = s.order_id")
     .whenMatchedUpdateAll()
     .whenNotMatchedInsertAll()
     .execute())

query = (df_stream.writeStream
    .format("delta")
    .foreachBatch(upsert_microbatch)
    .option("checkpointLocation", "abfss://chk@adls.dfs.core.windows.net/orders_chk")
    .start())
🔍 Code Breakdown & Engine Mechanics:
  • foreachBatch: Bridges Structured Streaming and standard batch APIs, allowing arbitrary Delta MERGE logic per microbatch partition.
  • Idempotent Commits: Using batch_id guarantees exactly-once processing even if a microbatch fails and replays from the checkpoint.
  • Multi-Table Fan-Out: A single stream can write to multiple Delta tables or external databases simultaneously within the microbatch function.
  • whenMatchedUpdateAll(): Dynamically syncs all columns between source and target without requiring explicit column-by-column mapping.
💡 Streaming Rule: Cache microbatch_df inside foreachBatch if reading it multiple times to prevent re-evaluating the streaming plan.
